Core Philosophy

소버린 AI
아키텍처

데이터 주권, 모델 주권, 인프라 주권을 모두 자체적으로 확보하여 외부 클라우드 API에 의존하지 않는 AI 시스템. 한국 금융기관의 핵심 규제인 망분리 규정을 100% 충족하는 유일한 아키텍처입니다.

🔐

데이터 주권 (Data Sovereignty)

모든 고객 데이터가 온프레미스에서 처리되며, 외부 API로의 전송이 제로입니다. 전자금융감독규정 제14조의2 완전 충족.

🧠

모델 주권 (Model Sovereignty)

한국산 오픈소스 LLM 3종(EXAONE, Solar Pro, Kanana)을 자체 서버에서 운영. 외부 모델 API 의존도 제로.

🏗️

인프라 주권 (Infra Sovereignty)

K3s 기반 경량 컨테이너 오케스트레이션으로 자체 인프라 운영. FuriosaAI NPU와의 전략적 협력으로 완전한 하드웨어 주권 확보 추진 중.

BRIDGE 01

Knowledge Versioning System

Git-for-Ontology
문제: 금융 규제 감사에서 "이 분석은 언제 버전의 지식으로 도출되었나?" 라는 질문에 답할 수 없다면, AI는 현장에 투입될 수 없습니다.
해결: 모든 온톨로지 변경을 Git처럼 커밋·롤백·브랜치 관리. 7-Gate HITL 승인 이력까지 체인으로 연결되어, "이 결론은 2026-04-02 14:23 버전의 지식에 근거했다"를 수학적으로 증명합니다.

BRIDGE 02 · CORE

Ontology-LLM Bridge

GraphRAG · The Heart of KIRI
문제: 일반 RAG는 텍스트 유사도 검색에 의존합니다. 그래서 "유치권과 선순위 가처분이 동시에 걸린 경매 물건"처럼 관계 기반 추론이 필요한 질문에서 무너집니다.
해결: 질의가 들어오면 온톨로지 그래프에서 관련 엔티티·관계·결정규칙을 먼저 탐색하고, 이를 LLM 프롬프트로 컴파일합니다. LLM은 "참고"하는 게 아니라 온톨로지에 갇힌 채로 추론합니다 — 환각 원천 차단.
GraphRAG Neo4j Cypher→Prompt SPARQL
BRIDGE 03 · CORE

3-Tier LLM Router

Cost-Accuracy Optimizer
문제: 모든 질의를 최상위 모델로 처리하면 GPU 비용이 폭발합니다. 반대로 경량 모델만 쓰면 복잡한 의사결정에서 신뢰도가 무너집니다.
해결: Query Complexity Classifier가 질의를 3단계로 분류 → 단순 조회는 경량(7B), 일반 분석은 중량(32B), 복잡한 추론은 전문가(70B+)로 자동 라우팅. 정확도는 유지하면서 GPU 비용 8배 절감을 달성한 핵심 메커니즘.
Query Classifier vLLM Load Balancer Cost Tracker
BRIDGE 04

HITL Gate Orchestrator

7-Gate State Machine
문제: "AI가 70% 생성, 전문가가 30% 검증"은 슬로건일 뿐입니다. 실제로는 어떤 산출물이, 어느 단계에서, 누구에게, 어떻게 전달되고 승인되는지 설계되어야 작동합니다.
해결: 모든 AI 산출물은 7개 Gate를 순차 통과. 각 Gate는 State Machine으로 관리되며, 전문가 승인 전까지 다음 단계로 진입 불가. 실패 시 Rollback Engine이 이전 안전 상태로 복원합니다.
Temporal State Machine Expert Queue Rollback
BRIDGE 05

MCP Integration Layer

Agent-to-System Bridge
문제: 7개 자율 에이전트(Sentinel·Finance·Legal...)가 분석만 하고 "읽기 전용"에 머무르면 생산성 도구 이상이 될 수 없습니다. DART·법원·국토부 시스템을 직접 호출할 수 있어야 합니다.
해결: Model Context Protocol(MCP) 서버로 외부 시스템을 표준화된 도구로 래핑. 에이전트는 망분리 환경 내에서 미러링된 데이터 소스를 안전하게 호출하며, 모든 호출은 감사 로그에 기록됩니다.
MCP DART Mirror 법원 Bridge Audit Log
BRIDGE 06

Airgap Sync Bridge

One-way Diode Protocol
문제: 망분리 환경에서 운영하면 "완벽한 보안"과 "업데이트 정체" 사이에서 선택해야 합니다. LLM 업데이트·온톨로지 신규 버전이 반영되지 못하면 AI는 시간이 지날수록 낡아집니다.
해결: 외부 → 내부로만 흐르는 단방향 다이오드 프로토콜. 모든 업데이트는 서명된 매니페스트와 델타 동기화로 무결성이 검증됩니다. 망분리를 유지하면서 AI는 계속 진화하는 유일한 구조.
